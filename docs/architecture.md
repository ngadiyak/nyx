# Nyx architecture

How the terminal is put together, where each kind of logic lives, and the invariants that hold it
up. The design spec (`docs/superpowers/specs/2026-09-03-nyx-terminal-design.md`, in Russian) is
the binding authority on *what*; this document is the working map of *where* and *why*.

## Modules

Five SwiftPM targets with one-way dependencies:

```
Nyx (Sources/NyxApp, AppKit)  ──▶  NyxRender (Metal + Core Text)  ──▶  NyxCore (pure Swift)  ──▶  CNyxPTY (C)
                              ╰─▶  NyxRemote (CryptoKit + URLSession) ─▶  NyxCore
nyx-bench (Sources/NyxBench)  ──────────────────────────────────────▶  NyxCore
```

| Target | Imports allowed | Job |
|---|---|---|
| `CNyxPTY` | libc | `forkpty` + `execve`, `TIOCSWINSZ`. Swift cannot `fork` safely and `posix_spawn` cannot set a controlling tty. |
| `NyxCore` | Foundation, CNyxPTY | Everything that decides something: parser, terminal model, selection, search, config, key/mouse encoding, layout trees, tab logic, shell-integration rules, sessions. **Never** AppKit, Metal, CoreText or QuartzCore. |
| `NyxRender` | Metal, CoreText, QuartzCore, NyxCore | Glyph atlas, fonts, instance buffers, shaders (compiled at runtime from a Swift string, because there is no `metal` compiler without Xcode), per-row redraw cache, synchronised-output gate. **Never** CNyxPTY. |
| `NyxRemote` | Foundation, CryptoKit, NyxCore | Remote sessions' I/O: the device identity and paired-devices files, the WebSocket to the relay with its handshake and reconnect, the per-attachment cipher, and the host/client orchestrators. Decides nothing a `NyxCore` value type could decide. **Never** AppKit, Metal or CNyxPTY. |
| `Nyx` (NyxApp) | AppKit + everything above | Windows, tab bar, split views, the `Pane` view, menus, settings window, config file watching, notifications, session save/restore, offscreen UI snapshots. Converts events; draws; decides nothing it could delegate. |

The rule behind the split: the build machine denies Accessibility and screen recording, so
nothing in a view handler can be exercised by a test or a script. Logic that sits in `NyxApp` is
logic nobody can verify. That is why even tab-bar geometry, divider hit-testing and the
"may I trust the dirty flags this frame" decision are `NyxCore` value types with tests.

## Data flow

```
 keyboard/mouse ─▶ Pane (NSView) ─▶ KeyEncoder / MouseEncoder (Core) ─▶ bytes ─▶ PTY.write
                                                                                     │
 PTY.read ◀──────────────────────────────────────────────────────────────────────────┘
    │  reader thread, 64 KB blocks
    ▼
 VTParserOf<Terminal> ─▶ Terminal (screen, scrollback, modes, palette, marks)   [under the session lock]
                              │ responses: [UInt8]  ─▶ written back to the PTY
                              │ events: [TerminalEvent] ─▶ Pane.handle (title, bell, cwd, clipboard, notification)
                              ▼
 display-link tick ─▶ Pane.render(): copies visible rows into a RenderFrame under the lock
                              ▼
 Renderer.render(frame, to: drawable)  ─▶ 3 instanced draw calls (backgrounds, glyphs, decorations)
```

**One `TerminalSession` per pane.** It owns the `PTY`, the reader thread, the `Terminal`, and a
lock. `withTerminal { }` is the only sanctioned way to touch a `Terminal`; the reference must not
escape the closure (a global search once did that and crashed under load).

**One `Renderer` per pane**, so one program's synchronised update cannot freeze another pane.

**At most one frame per vsync**, regardless of output volume. `cat` of a gigabyte never blocks the
UI because the reader thread only mutates the model; the display link decides when to draw.

## The model's invariants

These are the facts other code relies on. Break one and the symptom is "sometimes the terminal is
wrong", which nobody can reproduce.

- **Absolute rows.** Selection, search hits, command regions and folds are addressed by absolute
  row index (`scrollback count + screen row`), so they survive scrolling and new output.
  `Terminal.scrollbackGeneration` bumps whenever those indices stop meaning what they meant
  (`ED 3`, RIS, alt-screen swap) and deliberately *not* on resize; holders of absolute positions
  capture the generation and drop themselves when it moves.
- **`Row.dirty`** is set on every mutation and cleared only by `clearDirty(ifContentVersionIs:)`,
  which the pane calls after a frame was *presented* and only if `contentVersion` (bumped on every
  `feed`) did not move between building and presenting. `ViewportMapping.mayTrustDirtyFlags`
  says whether slot *y* still holds the row it held last frame; if not, the frame sends empty
  `dirtyRows`, which the renderer reads as "rebuild everything".
- **Scroll operations mark the whole region dirty.** That line is what makes the renderer's
  per-row cache correct across `IL`/`DL`/`SU`/`SD`/DECSTBM and alt-screen switches.
- **`Terminal.graphemes` is append-only.** A cell's `content` may point into it; a cached row's
  glyph can therefore never be re-pointed at a different cluster.
- **`Terminal` is not thread-safe.** The session serialises access; the reference must not leave
  `withTerminal`.
- **Synchronised output (DECSET 2026)** holds frames, never the model. `SyncOutputGate` is pure,
  takes its clock as a parameter, and expires after 150 ms so a program that dies mid-update cannot
  freeze the screen.
- **Prompt marks live on rows** (`Row.promptMark`, `commandStatus`, `commandDuration`,
  `inputStartColumn`, `exitStatus`) and survive reflow. Everything under "Because it knows where
  commands begin and end" in the README is derived from them, so a shell without integration
  gets none of it and the UI must degrade to plain terminal behaviour, never to silence.

## NyxRender

- `RenderFrame` is the whole contract: rows, graphemes, palette, cursor, focus, preedit,
  per-row selection / search / hovered link / notes / block spines / summaries, and `dirtyRows`.
  Built by the pane under the session lock; the renderer never sees a `Terminal`.
- `GlyphAtlas` rasterises through Core Text into a 2048² RGBA atlas (colour emoji share it), with
  `CTFontCreateForString` fallback. Its `generation` bumps on reset or font change, which also
  invalidates the renderer's row cache.
- **Row cache.** The renderer keeps the instances it built for each visible row and rebuilds a row
  only if its `RowKey` changed; `FrameKey` covers what changes every row at once (palette, metrics,
  cols, focus, atlas generation, cursor shape). Anything `buildRow` reads must be in one of the two
  keys, or a stale row will be drawn. `RenderStats` (`NYX_RENDER_STATS=1` in the app) measures
  it: a spinner should rebuild ~2 % of rows; a full repaint should rebuild all of them.
- `draw` returns `.presented`, `.held` (sync output) or `.noDrawable`; the pane clears dirty flags
  only on `.presented`.
- Chrome that AppKit draws (tab bar, search bar, palette, sheets, banners, settings) is not
  Metal and is rendered offscreen by `UISnapshot` instead; see `docs/testing.md`.

## NyxRemote

- `RelayConnection` is the device's one socket: handshake (`hello` → `challenge` → `auth` →
  `welcome`), reconnect with `Backoff`, and an outbox that queues what was sent while offline.
  Handshake messages are consumed there and never reach the delegate; everything after `welcome`
  is passed on verbatim, `error` included.
- `RemoteHost` publishes this Mac's sessions and answers attaches; `RemoteClient` attaches to
  someone else's. Both own serial queues, and the join between a snapshot and the live tail is a
  chunk *number*, not a timestamp: `Registration.sequence` is assigned on the host's queue, so a
  chunk fed before the snapshot but tapped after it still sorts below the cut-off and is not sent
  twice.
- `E2ESession` is one attachment's cipher: an ephemeral X25519 agreement signed by the device's
  Ed25519 identity (so the relay cannot substitute a key), then ChaCha20-Poly1305 with a
  per-direction counter, which is what makes a replayed or reordered frame a decryption failure
  rather than a screen artefact.
- Everything the coordinator owns is main-thread state, so all three `RelayConnectionDelegate`
  methods do nothing but hop to main. That hop is also what keeps a snapshot frame ahead of the
  live frame behind it — and it is why a hook that waits by spinning a nested `RunLoop` sees a
  remote session that never advances: libdispatch will not re-enter a main-queue drain.

**Config pipeline.** `ConfigStore` → `ConfigParser.parse` (line-numbered diagnostics; a bad line
leaves every other setting in force) → `ConfigDiff(old, new)` → `Pane.apply` / `TabController.apply`
consult the diff to rebuild only what changed. Settings that need a new session are named in the
banner rather than silently ignored (`ConfigDiff.deferredNotes`). The settings window and the
quick-action editor write through `ConfigWriter`, which edits lines in place so comments survive.

**Shell integration.** For zsh, `ShellIntegration.environment` points `ZDOTDIR` at
`Resources/shell-integration/zsh`, whose `.zshenv`/`.zshrc` shim sources the user's own files,
restores their `ZDOTDIR`, and sources `nyx-integration.zsh` (OSC 7 for cwd, OSC 133 A/B/C/D for
prompt marks with exit status). bash and fish get a `source` line shown in the settings window.
`shell-integration = off` disables injection. Nothing in the home directory is modified.

**Sessions.** On quit, every window's tabs, splits, cwd and scrollback go to `session.json` beside
the config. Restore is planned by `SessionRestore.plan` (Core); an unreadable or newer snapshot
gives one ordinary window. `restore-session = no` turns it off and clears the file.

## Performance model

- Parser and model are the hot path. `Package.swift` turns off dynamic exclusivity checks and turns
  on cross-module optimisation for release builds only; tests keep the checks.
- `nyx-bench` feeds a synthetic 96 MB stream (or a file) through `Terminal.feed` on a 200×50 grid.
  The floor is 180 MB/s locally (CI fails below 120 to absorb runner noise); measured 185–192.
- Remaining known headroom to the 300 MB/s target: table-driven parser, tracking actual row width,
  flat cell storage. All three rewrite tested code and are deferred until someone needs them.
- Idle CPU is 0 %: the display link pauses when a pane is occluded or has nothing dirty.
