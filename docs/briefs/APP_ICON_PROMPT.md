# Prompt: New Nyx App Icon

Design and implement a new macOS app icon for Nyx.

Context: the current icon feels unstylish and should be replaced with something more polished, native, and memorable. Nyx is a fast native macOS terminal built in Swift and Metal, with a focus on speed, clarity, command blocks, shell-native workflows, and agent-heavy development.

Current icon pipeline:
- Source drawing code: `scripts/make_icon.swift`.
- Icon build script: `scripts/make_icon.sh`.
- Final committed asset: `Resources/AppIcon.icns`.
- App bundling copies `Resources/AppIcon.icns` into `build/Nyx.app`.

Goal:
- Create an icon that feels like a serious modern macOS developer tool.
- It should read clearly at Dock size and still work at tiny sizes.
- It should avoid generic terminal clichés: plain `>_`, random neon gradients, fake glass blobs, overly literal windows, or busy sci-fi styling.
- It should feel native beside Finder, Terminal, Xcode, Warp, Ghostty, iTerm2, and system utilities.

Creative directions to explore:
- A sharp abstract mark based on terminal cells, prompt rhythm, command blocks, or a cursor trail.
- A minimal "Nyx" symbol that implies speed, structure, and depth without spelling the name.
- A dark, precise object with restrained contrast and one memorable accent color.
- A layered macOS-style icon with real silhouette, depth, and small-size legibility.

Deliverables:
1. Review the current generated icon and explain why it fails visually.
2. Propose 3 distinct icon directions with tradeoffs.
3. Pick the strongest direction and implement it in `scripts/make_icon.swift`.
4. Regenerate `Resources/AppIcon.icns` with `scripts/make_icon.sh`.
5. Verify generated PNG sizes before packaging.
6. Build the app bundle and confirm the icon is included.
7. Provide before/after notes and any remaining design risks.

Constraints:
- Keep the icon generation deterministic and reproducible.
- Prefer updating the existing Swift drawing pipeline over adding a binary-only source file.
- Do not depend on external design tools.
- Avoid changing unrelated app code.
- If a raster concept is useful, create it as reference only; the committed icon should still be generated by the project pipeline unless there is a strong reason not to.
