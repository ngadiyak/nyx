# Nyx — нативный терминал для macOS. Дизайн

Дата: 2026-09-03. Статус: черновик на утверждение.

## 1. Цель

Быстрый, лёгкий, нативный терминал для macOS, на который автор пересядет с iTerm2
для ежедневной работы (zsh, vim/neovim, htop, fzf, tmux, Claude Code, git).

Критерии успеха:

- Ввод и вывод ощущаются мгновенными: ни один ключ не «залипает», `cat` большого
  лога не подвешивает интерфейс.
- TUI-программы рисуются без артефактов, мышь в них работает.
- Вкладки, сплиты, выделение, копирование, поиск, кликабельные ссылки и пути.
- Настройка одним текстовым файлом с live-reload, несколько встроенных тем.
- Приложение запускается менее чем за 150 мс, в покое не ест CPU, бинарник
  без внешних зависимостей.

Не цели (сейчас): Linux/Windows, SSH-менеджер, встроенный AI, плагины,
профили как в iTerm2, полноценные настройки-GUI.

## 2. Ограничения окружения

- macOS 26.5, Swift 6.0.3, только Command Line Tools (без Xcode).
- Сборка через SwiftPM. `.app` собирает скрипт: `Info.plist`, иконка, ресурсы,
  ad-hoc codesign. Минимальная поддерживаемая macOS: 14 (Sonoma).
- Компилятора `metal` в CLT нет, поэтому шейдеры хранятся как исходник в Swift
  и компилируются на старте через `MTLDevice.makeLibrary(source:)`.
  Система кэширует результат; стоимость единицы миллисекунд.
- Внешних Swift-пакетов нет. Единственный не-Swift код: крошечный C-таргет для
  `forkpty` (в Swift `fork` небезопасен, а `posix_spawn` на macOS не умеет
  назначить controlling tty).

## 3. Архитектура

Три модуля с односторонними зависимостями: `NyxApp → NyxRender → NyxCore`,
плюс `CNyxPTY` (C) под `NyxCore`.

```
┌──────────────────────────────────────────────────────────────┐
│ NyxApp (AppKit)                                              │
│  окно, таб-бар, дерево сплитов, TerminalView (ввод, мышь,   │
│  IME), выделение, поиск, ссылки, конфиг, меню, сессии        │
└───────────────┬───────────────────────────┬──────────────────┘
                │ снимок экрана             │ байты ввода
┌───────────────▼───────────────┐ ┌─────────▼──────────────────┐
│ NyxRender (Metal + Core Text) │ │ NyxCore (чистый Swift)     │
│  атлас глифов, instance-буфер │ │  PTY, VTParser, Terminal   │
│  3 draw call на кадр          │ │  (Grid, Scrollback, режимы,│
│  перерисовка dirty-строк      │ │  OSC, ответы), Selection   │
└───────────────────────────────┘ └────────────────────────────┘
```

Правила границ:

- `NyxCore` не импортирует AppKit/Metal. Тестируется целиком unit-тестами.
- `NyxRender` не знает про PTY и ввод; на вход получает `ScreenSnapshot`.
- `NyxApp` не парсит escape-последовательности и не трогает ячейки напрямую.

### 3.1 Потоки

- **Reader-поток** (по одному на сессию): `read()` из PTY блоками до 64 КБ,
  сразу прогоняет через `VTParser`, который мутирует `Terminal`. Мутация под
  мьютексом сессии.
- **Главный поток**: AppKit, ввод. Ввод пишется в PTY через неблокирующую
  очередь записи (backpressure: если `write` вернул EAGAIN, копим и ждём
  `DispatchSource.write`).
- **Рендер**: `CADisplayLink` окна. На тик, если у сессии есть dirty-строки,
  берём мьютекс, копируем dirty-строки в снимок, отпускаем, рисуем. Максимум
  один кадр на vsync, независимо от объёма вывода. Так `yes` или `cat`
  гигабайтного файла никогда не блокируют UI.
- Режим синхронного вывода (DEC 2026) откладывает снимок до закрывающей
  последовательности, чтобы не было tearing в TUI.

## 4. NyxCore

### 4.1 CNyxPTY

`nyx_pty_spawn(cols, rows, argv, envp, cwd) -> {fd, pid}`: `forkpty`, в ребёнке
`chdir`, `execve`. Ребёнок ничего не делает между fork и exec, кроме `chdir` и
сброса сигнальных масок. Также `nyx_pty_resize(fd, cols, rows)` (TIOCSWINSZ).

Окружение шелла: наследуем, добавляем `TERM=xterm-256color`, `COLORTERM=truecolor`,
`TERM_PROGRAM=Nyx`, `TERM_PROGRAM_VERSION`, `LANG` если пуст. Шелл — из
конфига, иначе `$SHELL`, иначе `/bin/zsh`; запускается как login-shell (`-l`).

### 4.2 VTParser

Конечный автомат по Paul Williams (DEC ANSI parser): ground, escape,
escape-intermediate, csi-entry/param/intermediate/ignore, osc-string,
dcs-*, sos/pm/apc-string. UTF-8 декодер встроен в ground: невалидные байты
дают U+FFFD. Парсер не знает про экран, он вызывает `TerminalActions`:

```
print(scalar), execute(c0), csi(params, intermediates, final),
esc(intermediates, final), osc(bytes), dcsHook/put/unhook
```

Параметры CSI: до 32 параметров, подпараметры через `:` (нужно для SGR
`4:3` волнистого подчёркивания и `38:2:r:g:b`). OSC ограничен 64 КБ на
всякий случай (OSC 52 с большим буфером обмена).

### 4.3 Terminal и Grid

- `Cell` — 16 байт: `content: UInt32` (скаляр либо индекс в таблицу
  графемных кластеров, если кластер шире одного скаляра), `fg: UInt32`,
  `bg: UInt32` (упакованный цвет: 24 бита RGB + 8 бит тип: default /
  indexed / rgb), `attrs: UInt16` (bold, dim, italic, underline-стиль 3 бита,
  strike, inverse, blink, hidden, wide, wide-spacer), `hyperlink: UInt16`
  (0 = нет, иначе id в таблице OSC 8 ссылок).
- `Row` — массив `Cell` + флаги `wrapped` (мягкий перенос) и `dirty`.
- `Screen` — видимая сетка rows×cols, курсор, сохранённый курсор (DECSC),
  margins (DECSTBM), tabstops, charset G0/G1 (ASCII, DEC Special Graphics).
- `Scrollback` — кольцевой буфер строк, лимит из конфига (по умолчанию
  10 000 строк). Alt-экран без scrollback.
- `Terminal` — primary + alt `Screen`, режимы, палитра (256 + default
  fg/bg/cursor), заголовок, cwd (OSC 7), таблица гиперссылок, очередь
  ответов терминала (`responses: [UInt8]`, которые App пишет в PTY), очередь
  событий для App (`titleChanged`, `bell`, `cwdChanged`, `clipboardWrite`,
  `notification`, `promptMark`).
- Ширина символов: таблица `wcwidth` по Unicode 16 (генерируется скриптом в
  `Sources/NyxCore/Unicode/`), эмодзи и CJK ширины 2, combining ширины 0,
  VS16 делает ширину 2. Zero-width joiner склеивает кластер.
- Resize: primary-экран делает reflow по флагам `wrapped` (строки
  перескладываются под новую ширину, курсор сохраняет логическую позицию);
  alt-экран просто обрезается/дополняется, приложение перерисует само.

### 4.4 Поддерживаемые последовательности (этап 1)

- C0: BEL, BS, HT, LF, VT, FF, CR, SO, SI.
- ESC: 7/8 (DECSC/DECRC), D/E/H/M (IND/NEL/HTS/RI), c (RIS), `=`/`>`
  (keypad), `(`/`)` + charset, `#8` (DECALN для vttest).
- CSI: CUU/CUD/CUF/CUB/CNL/CPL/CHA/CUP/HVP, ED/EL (0,1,2,3), IL/DL/ICH/DCH/ECH,
  SU/SD, DECSTBM, SGR (полный: 0–9, 21–29, 30–37, 38, 39, 40–47, 48, 49,
  58/59 цвет подчёркивания, 90–97, 100–107), SM/RM и DECSET/DECRST для:
  1 (DECCKM), 3 (DECCOLM, игнор), 6 (DECOM), 7 (DECAWM), 12 (мигание), 25
  (DECTCEM), 1000/1002/1003/1005/1006 (мышь, SGR-кодирование), 1004 (фокус),
  1047/1048/1049 (alt-экран), 2004 (bracketed paste), 2026 (sync output),
  4 (IRM), 20 (LNM); DA1/DA2/DA3, DSR 5/6 (CPR), DECSCUSR (форма курсора),
  REP, CBT, TBC, XTWINOPS 14/16/18 (размеры), XTSAVE/XTRESTORE режимов,
  DECRQM (запрос режима), XTVERSION.
- OSC: 0/1/2 (заголовок), 4 (палитра set/query), 7 (cwd), 8 (гиперссылки),
  9 и 777 (уведомления), 10/11/12 (цвета fg/bg/cursor set/query), 52
  (буфер обмена: запись всегда, чтение только если включено в конфиге),
  104/110/111/112 (сброс цветов), 133 (A/B/C/D метки промпта, сохраняем
  в Row для этапа 3).
- DCS: принимаем и игнорируем, кроме `$q` (DECRQSS для SGR/DECSTBM).

Кодирование клавиш: xterm-совместимое (стрелки с DECCKM, `modifyOtherKeys`-
подобные CSI u для Ctrl/Alt комбинаций там, где иначе неоднозначно),
Option как Meta (ESC-префикс) настраивается в конфиге. Kitty keyboard
protocol — этап 3.

### 4.5 Selection (в Core, чтобы тестировать)

Модель выделения над логическими координатами (строка scrollback + столбец):
символьное, словесное (двойной клик, разделители из конфига), строчное
(тройной), прямоугольное (⌥). Извлечение текста учитывает мягкие переносы
(склеивает) и wide-spacer ячейки (пропускает). Выделение сохраняется при
прокрутке и при новом выводе (привязано к абсолютным строкам), сбрасывается
при очистке scrollback.

## 5. NyxRender

- `GlyphAtlas`: растеризация глифов через Core Text в атлас 2048×2048
  (RGBA8, чтобы цветные эмодзи жили в том же атласе; при переполнении
  второй атлас, при переполнении обоих — сброс и перерастеризация видимого).
  Ключ: (шрифт, glyph id, размер, стиль). Fallback-шрифт через
  `CTFontCreateForString` для отсутствующих глифов (кириллица в моно-шрифтах
  без неё, эмодзи, nerd-иконки). Рендер с учётом Retina scale, субпиксельное
  сглаживание выключено (как во всех GPU-терминалах), font smoothing
  настраивается.
- Кадр: три instanced draw call: фон ячеек (цветные квадраты), глифы
  (текстурированные квадраты), декорации (подчёркивания всех стилей,
  зачёркивание, курсор block/bar/underline, рамка курсора без фокуса,
  подсветка поиска/выделения). Instance-буфер пересобирается целиком при
  любом изменении (на 200×60 это 12k инстансов, менее 0.5 МБ, дешевле, чем
  умное частичное обновление); оптимизация по строкам отложена, пока не
  доказана профайлером.
- `CAMetalLayer` в `TerminalView`, `framebufferOnly`, тройная буферизация,
  `displaySyncEnabled`. Прозрачность и блюр окна через `NSVisualEffectView`
  за слоем (настройка `background-opacity`, `background-blur`).
- Шейдеры: один `.metal`-исходник как строковая константа Swift, компиляция
  при создании рендерера; при ошибке компиляции — fatal с текстом (это
  баг сборки, а не пользовательская ситуация).
- Лигатуры (шейпинг через Core Text по прогонам): этап 3. На этапах 1–2
  один глиф на ячейку.

## 6. NyxApp

### 6.1 TerminalView (NSView)

- Хостит `CAMetalLayer`, держит `TerminalSession` (Core) и `Renderer`.
- `NSTextInputClient`: IME (кириллица, dead keys, ввод эмодзи через
  Ctrl+⌘+Space, marked text рисуется поверх курсора).
- Клавиатура: `keyDown` → `KeyEncoder` (Core) → PTY. Хоткеи приложения
  перехватываются до этого через меню/`KeyBindings`.
- Мышь: выделение, если приложение не запросило мышь или зажат ⌥ (override).
  Иначе отчёты мыши по режимам 1000/1002/1003 в SGR-кодировании. Колесо:
  scrollback на primary-экране, стрелки вверх/вниз на alt-экране
  (настраивается). Drag&drop файлов вставляет экранированный путь.
- Копирование: `⌘C`, copy-on-select (конфиг), middle-click paste (конфиг).
  Вставка: `⌘V` с bracketed paste, если режим включён; многострочная вставка
  с переводами строк спрашивает подтверждение только если конфиг
  `paste-confirm-multiline = true` (по умолчанию выключено).
- Курсор: мигание по конфигу, форма из конфига и DECSCUSR, рамка при потере
  фокуса.

### 6.2 Окна, вкладки, сплиты

- Своё окно `NSWindow` с полноразмерным контентом (`fullSizeContentView`),
  компактный собственный таб-бар над панелями (скрывается при одной вкладке
  по конфигу). Нативные вкладки окна не используем: они не дают сплитов
  внутри вкладки и медленно переключаются.
- Заголовок вкладки: OSC 0/2, иначе имя foreground-процесса + последний
  сегмент cwd. Индикатор активности в неактивной вкладке (был вывод) и
  колокольчик.
- Дерево сплитов: `SplitNode = leaf(Pane) | split(axis, ratio, first, second)`.
  Собственный layout-view с перетаскиваемыми разделителями (толщина 1 pt,
  зона захвата 6 pt). Фокусная панель подсвечена тонкой рамкой (цвет из темы).
- Новая вкладка/панель наследует cwd текущей панели (из OSC 7, а если
  интеграция шелла не сработала, из `proc_pidinfo` foreground-процесса).
- Хоткеи по умолчанию (переопределяются в конфиге):

  | Действие | Клавиши |
  |---|---|
  | Новая вкладка / закрыть | ⌘T / ⌘W |
  | Вкладки 1–9, следующая/предыдущая | ⌘1…⌘9, ⌘⇧] / ⌘⇧[ |
  | Сплит вертикально / горизонтально | ⌘D / ⌘⇧D |
  | Фокус между панелями | ⌘⌥← ↑ → ↓ |
  | Развернуть панель на всю вкладку (toggle) | ⌘⇧⏎ |
  | Ресайз панели | ⌘⌃← ↑ → ↓ |
  | Поиск | ⌘F, ⌘G / ⌘⇧G далее/назад |
  | Очистить экран и scrollback | ⌘K |
  | Шрифт больше/меньше/сброс | ⌘+ / ⌘- / ⌘0 |
  | Открыть конфиг | ⌘, |
  | Перезагрузить конфиг | ⌘⇧, |

- `⌘W` на последней панели последней вкладки закрывает окно; если в панели
  жив дочерний процесс, кроме шелла (по `proc_listchildpids`), спрашивает
  подтверждение (конфиг `confirm-close-process`).

### 6.3 Поиск

`⌘F` показывает полоску сверху панели. Инкрементальный поиск по видимому
экрану и scrollback, регистронезависимый по умолчанию, переключатели
«регистр» и «regex» (NSRegularExpression). Совпадения подсвечиваются,
текущее выделено сильнее; ⏎/⇧⏎ ходят по ним, панель скроллится к текущему.
Esc закрывает и оставляет текущее совпадение выделенным (можно ⌘C).
Поиск выполняется в фоне по снимку строк, чтобы не блокировать ввод на
больших буферах.

### 6.4 Ссылки и пути

- OSC 8 гиперссылки: подчёркивание при наведении с ⌘, клик открывает.
- Авто-детект URL по regex (`https?://`, `file://`, `mailto:`, `ssh://`).
- Пути файлов: паттерн `(~|\.{1,2})?/?[^\s:'"()<>]+(:\d+(:\d+)?)?`. Кандидат
  проверяется на существование относительно cwd панели; строка/столбец
  отбрасываются. Открытие через `NSWorkspace.open` (эквивалент `open`).
  Конфиг `open-file-command` позволяет заменить на шаблон с `{file}` `{line}`.
- Детект делается лениво: только при удержании ⌘ и только для строки под
  курсором, поэтому не стоит ничего при обычной работе.

### 6.5 Конфиг

Файл `~/.config/nyx/config` (переопределяется `NYX_CONFIG`). Формат:
`ключ = значение`, `#` комментарии, ключи могут повторяться там, где это
список (`keybind`). Live-reload через `DispatchSource` на директорию;
ошибки показываются неблокирующим баннером с номером строки, а предыдущий
рабочий конфиг остаётся в силе. `⌘,` открывает файл через `open -t`,
создав его с закомментированными значениями по умолчанию, если не было.

Ключи этапа 2 (значения по умолчанию в скобках):

```
font-family        (Menlo)          font-size (13)      line-height (1.0)
font-thicken       (false)          theme (nyx-dark)    cursor-style (block)
cursor-blink       (true)           scrollback-lines (10000)
padding            (8)              background-opacity (1.0)   background-blur (0)
shell              ($SHELL)         working-directory (inherit | home | /path)
copy-on-select     (false)          middle-click-paste (true)
option-as-meta     (left | right | both | none; по умолчанию none)
mouse-scroll-alt-screen (arrows)    bell (visual | sound | none; visual)
confirm-close-process (true)        clipboard-read (false)   # OSC 52 чтение
tab-bar            (auto | always | never)   window-decorations (true)
word-separators    ( " ()[]{}'\"`,;:|<>")
open-file-command  ()               # пусто = NSWorkspace.open
keybind            = cmd+t=new_tab  # список, синтаксис ghostty-подобный
palette            = 0=#1a1b26      # переопределение цветов темы
```

Темы: встроенные `nyx-dark` (дефолт), `nyx-light`, `solarized-dark`,
`gruvbox-dark`, `dracula`, `catppuccin-mocha`, `one-dark`. Тема следует
системному Dark/Light, если задано `theme = dark:<a>,light:<b>`.

**Не реализовано:** кастомная тема файлом в `~/.config/nyx/themes/<имя>`.
Парсер (`Themes.parse`) написан и покрыт тестами, но его никто не
вызывает — `Pane.resolvedPalette` берёт палитру прямо из `Themes.builtin`.
Пока цвета переопределяются только строкой `palette` в самом конфиге.
Подключение файлов тем — отдельная задача: чтение домашней директории из
NyxCore, слежение за файлом и приоритет над встроенными.

### 6.6 Интеграция с шеллом

При старте zsh подкладываем `ZDOTDIR` с нашим `.zshenv`, который источает
пользовательские файлы и добавляет хуки для OSC 7 (cwd) и OSC 133 (метки
промпта). Отключается `shell-integration = false`. Для bash/fish на
этапе 2 только OSC 7 через `PROMPT_COMMAND`/событие `fish_prompt`,
если это не ломает пользовательский конфиг; иначе fallback на `proc_pidinfo`.

### 6.7 Сессии

При выходе сохраняем в `~/Library/Application Support/Nyx/session.json`
раскладку окон, вкладок, сплитов и cwd каждой панели. При запуске
восстанавливаем (конфиг `restore-session = true`). Содержимое scrollback
не сохраняется (этап 3).

### 6.8 Меню и прочее

Стандартное меню macOS со всеми действиями и их хоткеями (Nyx, File, Edit,
View, Window, Help), чтобы все действия были обнаружимы. Уведомления
(OSC 9/777, bell в нефокусной вкладке) через `UNUserNotificationCenter`.
Поддержка `open -a Nyx /path` и `nyx` CLI-скрипт в бандле, открывающий
папку в новой вкладке.

## 7. Обработка ошибок

- Процесс в панели завершился: панель показывает строку
  `[процесс завершился с кодом N]`, ⏎ перезапускает шелл, ⌘W закрывает.
  Конфиг `exit-behavior = hold | close | restart` (hold).
- Не удалось создать PTY / запустить шелл: alert с текстом errno, панель
  закрывается.
- Ошибка конфига: баннер, предыдущий конфиг сохраняется.
- Metal недоступен: alert и выход (на поддерживаемых Mac невозможно).
- Переполнение OSC/DCS: последовательность обрывается и игнорируется.
- Невалидный UTF-8: U+FFFD, парсер не ломается.

## 8. Производительность: цели и как измеряем

| Метрика | Цель | Как мерим |
|---|---|---|
| Холодный старт до промпта | < 150 мс | `time` от запуска до первого OSC 133 A |
| Задержка клавиша → пиксель | ≤ 1 кадр (8 мс @120 Гц) | Typometer-подобный тест, ручная проверка |
| Пропускная способность парсера | ≥ 300 МБ/с (этап 3); достигнуто 189 МБ/с | `nyx-bench` прогоняет файлы через `VTParser+Terminal` |
| `cat` файла 1 ГБ | UI не замерзает, ≤ 1 кадр/vsync | ручная проверка |
| CPU в покое | 0 % | Activity Monitor |
| Память, 1 вкладка, пустой scrollback | < 60 МБ | Activity Monitor |
| Размер бинарника | < 5 МБ | `du` |

Бенчмарк-таргет `nyx-bench` входит в репозиторий, гоняется вручную и перед
релизами.

**Статус на конец этапа 1.** Замер на смешанном потоке с большой долей
escape-последовательностей: 189 МБ/с (было 14 МБ/с в первой реализации, рост в
13,4 раза). На чистом ASCII без escape-последовательностей: 424 МБ/с. Для
сравнения, iTerm2 на том же классе задач держит десятки МБ/с, так что цель
«быстрее существующих решений» на этапе 1 выполнена. Оставшийся разрыв до
300 МБ/с требует трёх структурных изменений, каждое из которых переписывает уже
покрытый тестами код, поэтому они отложены на этап 3: табличный автомат вместо
switch в `VTParser`, отслеживание фактической ширины строки (чтобы не трогать
хвост из пробелов) и плоское хранение ячеек одним массивом вместо массива строк.

## 11. Этапы

**Этап 1 — ядро.** CNyxPTY, VTParser, Terminal с §4.4, GlyphAtlas, Renderer,
TerminalView с клавиатурой и IME, ресайз, scrollback колесом, одно окно,
одна панель, конфиг только `font-*` и `theme` захардкожены. Готово, когда
vim/htop/fzf/Claude Code работают без артефактов и `cat` большого файла не
подвешивает UI.

**Этап 2 — ежедневный драйвер.** Вкладки, сплиты, выделение и копирование,
вставка, мышь в TUI, поиск, ссылки и пути, полный конфиг с live-reload,
темы, интеграция с шеллом, сессии, меню, уведомления, бандл и установка в
/Applications. Готово, когда автор неделю работает только в Nyx.

Финальный ревью этапа 1 добавил в этот список три пункта, обещанные, но не
сделанные:

- **CSI u (modifyOtherKeys) для неоднозначных сочетаний.** Клаузула о
  кодировании клавиш в §4.4 подразумевает её; сейчас ctrl+Tab и ctrl+Enter
  уходят в приложение неотличимо от Tab и Enter. Нужен режим CSI u поверх
  `KeyEncoder`.
- **Построчная частичная перерисовка через `Row.dirty`.** §3 обещает её;
  флаг честно выставляется на каждой мутации, но рендерер пересобирает все
  строки каждый кадр и никто `dirty` не читает.
- **DECSET ?2026 (synchronised output) не влияет на рендер.** Режим
  парсится и корректно отдаётся по DECRQM, но кадр не удерживается на время
  синхронизированного блока, то есть разрывов он пока не предотвращает.

Ещё три пункта финальное ревью отметило как латентные: на этапе 1 они
недостижимы, но становятся живыми ровно тогда, когда появятся вкладки и
сплиты. Их стоит закрыть первыми, до новой функциональности:

- **`TerminalView.isOccluded` не сбрасывается в `viewDidMoveToWindow`.**
  Пока вью живёт в одном окне, флаг всегда корректен. Как только вью
  переносится между окнами (вкладки, сплиты), перенесённая скрытая панель
  останется с `isOccluded = true` и перестанет перерисовываться, пока
  AppKit не пришлёт уведомление на новом окне. Лечится одной строкой.
- **`TerminalModes.keypadApp` пишется DECKPAM/DECKPNM и не читается никем.**
  Application keypad — реальное поведение xterm, которого у нас нет:
  цифровая клавиатура в приложениях вроде vim шлёт обычные цифры вместо
  SS3-последовательностей.
- **Повтор кадра при отсутствии drawable станет некорректным** вместе с
  построчной перерисовкой: `render()` вызывает `clearDirty()` до того, как
  узнаёт, что кадр не отрисовался, так что повтор нарисует «чистые» строки.

**Этап 3 — умные фичи (roadmap, отдельная спека).** Навигация по меткам
промптов и блоки команд, сохранение scrollback в сессии, лигатуры и шейпинг,
Kitty keyboard protocol, Kitty graphics / Sixel, quick-terminal (hotkey
window), быстрый переключатель вкладок/панелей по имени, экспорт буфера.

## 12. Открытые решения, принятые по умолчанию

- Формат конфига: плоский `ключ = значение`, а не TOML/JSON: без зависимостей
  и парсится за микросекунды. Если понадобятся вложенные структуры, это
  сигнал, что фича переусложнена.
- Шрифт по умолчанию Menlo (есть на каждом Mac); пользовательские
  моношрифты с nerd-иконками работают через fallback.
- Ligatures отложены сознательно: шейпинг по прогонам заметно усложняет
  рендер и кэш; сначала база.
